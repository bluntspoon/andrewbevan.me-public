Depth — A1–A25
A1Value vs reference types in .NET
  • Value type: holds data directly. Copied on assignment / parameter pass. Structs, primitives, enums.
  • Reference type: holds a pointer to a heap object. Assignment copies the pointer; both vars point at the same object. Classes, arrays, strings, delegates.
  • string is reference but immutable — feels value-like.
  • Boxing: assigning a value type to object or interface — heap allocation + copy.
Trap: Mutating a struct through an interface mutates the boxed copy, not the original. Looks like a no-op bug.
A2Big-O / collection complexity in .NET
  • List<T>: O(1) append, O(n) insert/remove mid, O(n) search.
  • Dictionary / HashSet: O(1) avg, O(n) worst (collisions). Not thread-safe.
  • SortedDictionary: O(log n), iterates in key order.
  • ConcurrentDictionary: striped locks. Use AddOrUpdate / GetOrAdd for atomic compounds.
Trap: Dictionary enumeration order is undefined. Don't rely on insertion order.
A3Bitwise operators — when do you use them?
  • & test, | set, &~ clear, ^ toggle.
  • << / >> = ×/÷ powers of 2.
  • Uses: [Flags] enums, packing small fields, hash-mixing.
Trap: Signed >> sign-extends — shifting a negative stays negative. Use unsigned or C# 11's >>>.
A4Unicode & encoding — what breaks?
  • UTF-8: 1–4 bytes, ASCII-compatible, default for files and wire.
  • UTF-16: .NET / Java string internal; surrogate pairs for codepoints > U+FFFF.
  • string.Length returns code units, not characters.
  • Normalise (NFC) before compare or hash.
Trap: Truncating a UTF-16 string at an arbitrary index can split a surrogate pair → invalid string.
A5JSON vs Protobuf vs Avro
  • JSON: human, schemaless, large, slow. Public APIs.
  • Protobuf: binary, schema-driven, compact, fast. Don't reuse field numbers. gRPC default.
  • Avro: schema registry, Kafka common, strong evolution.
Trap: Proto3 can't distinguish default value from absent. Use 'optional' or wrappers when nullability matters.
A6TCP vs UDP — when would you pick UDP?
  • TCP: reliable, ordered, congestion-controlled. HTTP, gRPC, SQL.
  • UDP: fire-and-forget, low latency. DNS, NTP, VoIP, video.
  • QUIC: UDP + reliability + multiplexing in user-space. HTTP/3 runs on it. No TCP head-of-line blocking.
Trap: 'UDP is faster' is misleading. TCP wins bulk; UDP wins small + latency-sensitive.
A7Mutex primitives — pick one for X
  • Monitor (lock): in-process, reentrant, cheap. Default.
  • Mutex: kernel object, named, cross-process. Slow.
  • SemaphoreSlim: counting, async-friendly (WaitAsync).
  • ReaderWriterLockSlim: many readers / one writer.
  • Spinlock: busy-wait, very short sections only.
  • Interlocked: lock-free CAS for single variables.
Trap: Never lock(this), lock(typeof(X)), lock("string"). Use private readonly object.
A8CAP & eventual consistency — pick CP or AP for jackpot ledger
  • Under partition: choose Consistency or Availability.
  • CP for ledger writes — refuse rather than diverge.
  • AP for read paths (leaderboards, dashboards).
  • Eventual consistency must specify staleness window + conflict rule.
Trap: 'Eventually consistent' with no number is hand-waving. Always quote the window.
A9Compiled vs interpreted — what does .NET do?
  • C# → IL (Roslyn) → JIT compiles to machine code on first call (RyuJIT).
  • Tiered JIT re-compiles hot methods more aggressively.
  • AOT: build-time native; faster start, less peak.
  • GC: generational (Gen 0/1/2 + LOH). Server GC for throughput.
Trap: 'Compiled' is binary thinking — modern .NET is JIT with tiered + AOT options.
A10REST vs gRPC vs GraphQL
  • REST: ubiquity, browser-friendly, cacheable. Public APIs.
  • gRPC: IDL, HTTP/2, streaming, fast. Internal service-to-service.
  • GraphQL: client-shaped queries, hard caching, needs query budget.
  • Idempotent: GET / PUT / DELETE; POST needs an idempotency key.
Trap: Most 'REST' is RPC-over-HTTP. Don't argue Roy Fielding orthodoxy.
A11Stateful vs stateless apps — what's the cost of state?
  • Stateless: any instance handles any request → easy horizontal scale.
  • Stateful: pinned by key (sticky / actor) → low latency, harder to scale and fail over.
  • Externalise state (Redis, SQL) → stateless again, at a network-hop cost.
Trap: Sticky sessions look stateless but hide a hot-shard problem.
A12AG vs SAN (SQL Server HA)
  • Always On AG: each replica owns its data, log-shipped. Sync (RPO=0, latency cost) or async. Readable secondaries. Cross-DC.
  • SAN FCI: shared disk, active/passive nodes. SAN is SPOF.
  • Modern default = AG. FCI lingers on licensing.
Trap: AG sync mode adds commit latency = replica RTT. State this explicitly.
A13JWT, certs, password hashing — when is JWT wrong?
  • JWT (signed): stateless auth. Can't revoke before expiry without a denylist (defeats stateless).
  • JWE: encrypted claims.
  • mTLS for service-to-service. Prefer short-lived certs.
  • Passwords: Argon2id / bcrypt — never plain SHA.
Trap: JWT in localStorage = XSS-stealable. Use httpOnly + SameSite cookies.
A14Test pyramid + kinds
  • Unit (broad base): ms, no I/O.
  • Integration: real DB / broker / HTTP.
  • Contract (Pact): consumer-driven, guards inter-service compatibility.
  • E2E: full system, slow, few golden flows.
  • Property-based for invariants. Mutation testing to verify the suite.
Trap: Ice-cream-cone (lots of E2E, few units) is slow, flaky, expensive.
A15How does async/await actually work?
  • Compiler rewrites the method into a state-machine struct (IAsyncStateMachine).
  • Each await: save locals, hook continuation onto the Task, return the thread.
  • Continuation runs on captured SynchronizationContext unless ConfigureAwait(false).
  • async does not spawn threads. CPU-bound work needs Task.Run.
  • ValueTask<T> reduces allocations on already-completed paths.
Trap: .Result / .Wait() in a sync context (UI / classic ASP.NET) deadlocks. Use ConfigureAwait(false) in libs.
A16Virtual memory — what does it buy?
  • Each process sees an isolated flat address space.
  • MMU + page tables map virtual → physical. TLB caches recent translations.
  • Paging: cold pages swap to disk. Thrashing = death.
  • Memory-mapped files for DBs.
  • Copy-on-write at fork.
Trap: 'OOM' usually means address-space / commit-charge limit, not literal RAM. Read the actual error.
A17Mutex cost — kernel vs user mode
  • Uncontended: a few cycles (atomic CAS).
  • Contended: kernel mode → context switch → microseconds.
  • Prefer Interlocked > Monitor > Mutex.
Trap: Fine-grained locks can be slower than one coarse lock when contention is low. Measure.
A18Architecture patterns — monolith vs microservices vs event-driven
  • Monolith: one deployable, ACID-easy. Modular monolith preserves boundaries.
  • Microservices: independent scale / deploy / language. Cost: distributed txn, network failures, ops.
  • Event-driven: broker decouples producers/consumers. Hard end-to-end reasoning.
  • N-tier: presentation / business / data — historic default.
Trap: Distributed monolith — services that must deploy together. Worst of both.
A19Hexagonal / Clean architecture
  • Ports & Adapters: domain at centre, infra at edge behind interfaces.
  • Dependency rule: dependencies point inward.
  • Domain knows nothing about SQL or HTTP.
  • Pays off for rich domains; ceremony for thin CRUD.
A20UML diagram types — pick one
  • Use case: actor goals.
  • Activity: workflow / process with parallelism.
  • Sequence: time-ordered messages between components. Most-used.
  • Class: static structure, multiplicities, relationships.
  • Component / deployment: services / physical placement.
  • State: lifecycle of one entity.
Trap: Don't draw a class hierarchy when the question is about a system. Match diagram to question.
A21Scrum vs Kanban vs #noestimates
  • Scrum: time-boxed sprints, ceremonies. Predictable cadence.
  • Kanban: continuous flow + WIP limits. Ops-heavy / interrupt-driven work.
  • #noestimates: slice work uniformly small, count throughput. A lens, not a religion.
A22DevOps — what's in your pipeline?
  • CI: lint → build → unit → integration → SAST/SCA → container → registry.
  • CD: dev → smoke → canary → prod, auto rollback on SLI burn.
  • Everything-as-code: Terraform / Bicep / Helm / pipeline YAML, PR-reviewed like app code.
Trap: Click-ops on infra has the same blast radius as code, but skips review.
A23False cache-line invalidation — what is it and how do you fix?
  • CPU caches in 64-byte lines.
  • Two threads writing different vars on the same line bounce the line between cores (MESI) → throughput collapses.
  • Fix: pad hot vars to separate lines.
  • .NET: [StructLayout(Explicit)] + [FieldOffset(64)]. Java: @Contended.
  • Memory model: L1 ~1ns • L2 ~3ns • L3 ~10ns • RAM ~100ns • SSD ~100µs • net ~ms.
Trap: Padding without profiling wastes cache bandwidth. Measure with perf counters first.
A24Containers — what's actually shared with the host?
  • Containers share the host kernel; package app + deps + config.
  • Linux primitives: namespaces (isolation), cgroups (limits), union FS (layers).
  • WSL2 = real Linux kernel in lightweight VM.
  • Pin images by digest, not tag.
Trap: 'Lightweight VM' is wrong threat model — kernel exploit escapes the container.
A25Kubernetes — Pod / Deployment / Service / Ingress
  • Pod: smallest unit, shared net/storage.
  • Deployment: rolling updates over a ReplicaSet.
  • Service: stable virtual IP for selector-matched pods.
  • Ingress: L7 routing, TLS termination.
  • Probes: liveness (restart), readiness (drop from LB), startup (slow boot).
Trap: Liveness probe that calls a downstream = cascading restarts when dep is sick.
Breadth — B1–B40
B1CAP / PACELC
Under partition: pick C or A. Else (no partition): trade Latency vs Consistency. Anchor in domain NFRs.
B2Consistency models — strong / eventual / causal
Strong = always latest (balances). Eventual = converges (catalogues). Causal = preserves cause-effect. Plus read-your-writes / monotonic / session compromises.
B3Consensus (Raft)
One leader per term. Leader replicates log. Entry committed once a majority quorum has it. Safety = quorum + persistent term/log + leader election with jitter.
B4Idempotency — design an idempotent credit API
Client UUID per intent. Server stores (key, result) in dedupe table with TTL. Repeat returns original result without re-executing.
B5Exactly-once vs at-least-once
Network exactly-once is impossible. Achievable as exactly-once processing via at-least-once delivery + idempotent consumer / transactional outbox.
B6Clocks & time
Wall-clock unsafe across nodes (skew). Use logical (Lamport, vector) or hybrid logical clocks (HLC). TrueTime is rare.
B7Leader election & split-brain
Quorum-based election (overlapping majorities). Fencing tokens reject stale-leader writes. Lease-based leadership with renewal.
B8Partitioning & sharding
Sharding key spreads load. Mitigate hot shards: sub-sharding, read replicas, write offload. Consistent hashing reduces reshard cost. Keep common path single-shard.
B9Kafka vs Service Bus
Kafka = log-structured, replay-friendly, partition-ordered. Service Bus = queue/topic, per-message ack, sessions for ordering. Kafka pushes cost to storage; SB to per-op.
B10Ordering guarantees
Kafka: partition by key → ordered within. Service Bus: sessions keyed → FIFO consumer. Process synchronously per key downstream.
B11Back-pressure
Bounded queues (push back). Scale consumers. Shed low-priority load. Autoscale on queue-depth. Never unbounded buffers.
B12DLQ & poison messages
After N failures → DLQ with full context. Alerts on non-zero depth. Replay tooling. Classify: transient (retry), poison (DLQ), data-quality (quarantine).
B13OLTP vs OLAP
OLTP = row-oriented, normalised, point writes / short reads. OLAP = columnar, denormalised, wide scans + aggregates. Move via CDC → ClickHouse / Synapse.
B14SQL indexing
Indexes speed reads, slow writes, cost storage. Add when plan shows scan/lookup. Covering indexes eliminate lookups. Composite: leftmost-prefix. Drop unused.
B15Transaction isolation levels
Read Committed (no dirty) → Repeatable Read (no non-repeatable) → Snapshot/MVCC (consistent snapshot, no blocking) → Serializable (full).
B16Sharding vs replication
Replication = same data many copies (read scale + HA). Sharding = different data on different nodes (write scale). Usually combined: shard then replicate.
B17ClickHouse — why for jackpot analytics?
Columnar + vectorised. MergeTree family. Materialised views maintain aggregates on insert → second-fresh dashboards. Not OLTP. Batch inserts, never per-row.
B18Query tuning a regression
Capture actual plan, compare to last-known-good. Check parameter sniffing, stale stats, data skew. Fix: update stats, add index, OPTION RECOMPILE, Query Store force plan.
B19Circuit breakers
Closed → Open (fail fast) → Half-open (probe). Driven by failure rate or latency. Polly composes breaker + retry + timeout. Half-open probe policy matters.
B20Timeouts & retries
Timeouts shorter than upstream's. Exponential back-off + jitter. Cap retries. Distinguish idempotent (safe) from non-idempotent.
B21Bulkheads
Isolate resources per tenant/class so one noisy tenant can't starve others. Separate thread/connection pools or pod boundaries. e.g. VIP wager pool.
B22Chaos testing
Inject failures with blast-radius control. Steady-state hypothesis tied to SLO. Stage → game days → automated chaos in prod. Without SLOs it's theatre.
B23OWASP Top 10 — defenses
Injection: parameterised queries + least-privilege. Broken auth: OIDC + MFA + rate limit. SSRF: outbound allowlist, block metadata endpoints, careful URL parsing.
B24OIDC / OAuth2 PKCE
Client sends code_challenge (SHA256 of code_verifier). IdP returns code. Client exchanges code + verifier for tokens. Defeats code interception on public clients.
B25Crypto basics
AES-GCM = symmetric, bulk. RSA/ECDSA = asymmetric, slow, key-exchange + signatures. SHA-256 = hash, integrity. Argon2id/bcrypt for passwords. Never home-brew.
B26TLS 1.3
1-RTT handshake (0-RTT for resumption — replay risk). Removed legacy ciphers. All post-ServerHello messages encrypted. PFS mandatory.
B27Secrets management
Never in source. Key Vault / HashiCorp Vault, RBAC-scoped, per-env. Prefer short-lived managed-identity tokens. Rotate automatically. Avoid env-vars (crash dumps leak).
B28TCP handshake & lifecycle
SYN / SYN-ACK / ACK establishes seq numbers + windows. Congestion control (Reno/CUBIC/BBR). FIN/ACK + TIME_WAIT 2×MSL — can exhaust ephemeral ports under high churn.
B29HTTP/1.1 vs 2 vs 3
1.1: connection-level head-of-line. 2: multiplexed streams over one TCP, binary, HPACK. 3: QUIC over UDP, no TCP HOL, faster handshake.
B30L4 vs L7 load balancing
L4 routes IP:port, fast, dumb. L7 routes by host/path/header, can do auth/retries/canary. Pattern: L4 front + L7 inside platform. L4 hot-spots gRPC connections.
B31DNS TTL trade-offs
Low TTL = faster failover, more traffic. High TTL = cheaper, slower to react. Resolver caches and runtime caches (older Java/.NET) bound real reactivity.
B32Logs / metrics / traces
Logs: high-cardinality narrative, expensive. Metrics: low-cardinality, dashboards/alerts. Traces: per-request causal chain across services. OpenTelemetry standard.
B33RED & USE methods
RED (services): Rate, Errors, Duration. USE (resources): Utilisation, Saturation, Errors. Per-endpoint RED beats service-wide averages.
B34SLO / SLI / SLA + error budget
SLI = measure. SLO = internal target. SLA = contractual (with consequences). Error budget = 1 − SLO. Burn fast → slow deploys; fat → ship.
B35Managed vs self-hosted
Managed buys ops at premium. Self-host buys control + cost-at-scale at ops cost. Decide on criticality, expertise, compliance. 'Managed' ≠ zero-ops (you still own schema, quotas, cost).
B36AKS / Kubernetes basics
Pod evicted under memory pressure: check requests vs limits, QoS class (BestEffort → Burstable → Guaranteed), node events, VPA/HPA history. CPU throttling is silent.
B37Terraform patterns
State must be remote (Azure Storage) with lock + versioning. Module boundaries = blast radius. Drift detection: scheduled plan in CI. Don't store secrets in state.
B38Trunk-based development
Short-lived branches, frequent merges → smaller diffs, easier review. Feature flags decouple deploy from release. Requires strong CI + flag hygiene.
B39Blue-green / canary / feature flags
Blue-green = swap whole env, instant rollback, double infra. Canary = traffic slice, monitor, progress. Flags = runtime per-user, granular but ops cost. Stale flags rot.
B40async vs threads (.NET)
async for I/O-bound (frees thread). Dedicated thread for long-running CPU work. Avoid Task.Run in ASP.NET request paths for I/O. ConfigureAwait(false) in libraries.
